Attestation policy sources:

- [Android verification guidance](https://developer.android.com/privacy-and-security/security-key-attestation): nearest-root extension, official revocations, factory-key date exemption and RKP date enforcement.
- [Android attestation schema](https://source.android.com/docs/security/features/keystore/attestation): authorization tags, boot state and application identity.
- [Official roots](https://android.googleapis.com/attestation/root), retrieved 2026-10-15. DER SHA-256: `cedb1cb6dc896ae5ec797348bce9286753c2b38ee71ce0fbe34a9a1248800dfc`, `6d9db4ce6c5c0b293166d08986e05774a8776ceb525d9e4329520de12ba4bcc0`.

The factory date exemption requires the first official root's exact SPKI, a four-certificate path with a root-issued intermediate carrying one serial-number subject attribute, and no RKP profile or provisioning extension. Its path is checked at the common certificate validity-window intersection; a path without an intersection is unsupported. Other paths use current time. The [official Kotlin classifier](https://github.com/android/keyattestation/blob/main/src/main/kotlin/provider/KeyAttestationCertPath.kt) distinguishes factory and remote provisioning by the intermediate profile. Google's [old-root RKP fixture](https://github.com/android/keyattestation/blob/main/testdata/caiman/sdk36/TEE_EC_RKP.pem) demonstrates that the RSA root alone does not identify factory provisioning. The [official validator](https://github.com/android/keyattestation/blob/main/src/main/kotlin/provider/KeyAttestationCertPathValidator.kt) restricts expired-certificate exceptions to factory provisioning.

The phone app signer and minimum package version are immutable build policy; either absent value refuses verification. A signing publisher must assign monotonically increasing package versions to security-relevant APK changes.

Revocations come only from an authenticated in-memory official HTTPS response. Transport must enforce origin, certificate verification, response bounds and Cache-Control revalidation/no-store semantics before constructing the opaque value. The verifier enforces a maximum 24-hour freshness window reduced by Age, monotonic expiry, wall-clock rollback refusal, strict schema and rejection of every listed status.
