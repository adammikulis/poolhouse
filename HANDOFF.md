## Faster testing and landing, in order of use
1. **Share the `team` fixture's setup, not the node.** A bare `workspace_node` costs about 0.35 s to start and 0.1 s to stop (about 4.6 CPU minutes over 690 tests); the rest of a node test's setup is `team`: registering members, enrolling the person key, and `board create` / `join-board` as subprocesses (0.6 s per test in `test_board_messages`, 1.6 s in `test_workspace_files`, where sharing the person key helps most). A module-scoped node is not safe as it stands: a fresh board per test hits the node's compiled quotas (16 new boards per hour and 60 registrations per minute per lineage, `app/poolhouse-node/src/node.rs`), and one shared board is not isolated because claims, announcements, digests and rooms are board-wide.
2. **`tests/test_gates_incremental.py` (about 316 s and 109 s on one worker)** runs eight incremental runs, each followed by a whole-repo full run. No run could be proved redundant: the cold pyright run fills the cache the last incremental run depends on, and the real-tree test covers roots the copy lacks. Leave it unless a checker is shown to repeat another's work.
3. **Measure the fixed cost of a scoped run:** it was 15 to 19 s before the overhead and broker fixes landed and has not been measured since. Time `scripts/test all` on three small files with `--durations` and fix what is above 5 s or a quarter of the wall time.
4. **Re-record `tests/ci-durations.json` from a complete CI run** (`scripts/ci_shards.py record --junit`): it comes from local history that counts child CPU, so shard 4 is overloaded and some files are 3 to 10 times off. This only matters for the nightly and pull-request runs.
Not worth doing: cutting parametrized cases (under 3 percent of the time), deleting tests (the cost sits in about 150 heavy tests, not in the count), and the landing path (a push waits for nothing).

# Release cut
- **Two audiences, one build:** a person on the desktop or phone app taps and reads plain sentences and never meets a terminal, key or port; a developer using the library keeps their workflow with no new flag, prompt or wait, and gets the same protection. A release item that adds a visible step for either is redesigned first.
- **Existing harnesses are the way in:** Claude Code, Codex and other coding agents work through hooks, settings and the library with no change to how they are launched or used; the release is checked by driving one of them through a pool journey, not by tests alone.
- **Blocks a release:** the release signing key (owner terminal); `scripts/github-protection-apply` (owner terminal); phone-signed charters so a real pool can be founded; the access-widening fixes (subagent as lead, authority loosening, protected paths, person-record forgery, hook coverage); the backdoored-model slices B2, B4, B5 and B6; refusing pools founded before F1 (owner decided 2026-10-13: a charter version bump sets them aside and a person founds a new pool).
- **A refused or shut-down pool is deleted after 3 days** (owner, 2026-10-13), kept until then so a person can change their mind; the node does the delete, and a person can restore it inside the window. A pool shut down for compromise is frozen, sealed read-only with its keys and grants revoked, never restorable, and a person founds a new one; the 3 days delete only its live state and secrets, and the sealed record stays until a person deletes it (owner, 2026-10-13). Not built.
- **Not in the first release:** the Box enforcer, decoys, two-box layering and lab mode (`docs/strands-box.md`); the default stays the Poolhouse proxy and kernel sandbox.
- **The scripts that check a push start Python with the pushing environment's `PYTHONPATH`:** `scripts/hooks/pre-push` starts `pushed` and `person-consume` as `"$python" script` with no `-I`, so a `sitecustomize.py` or a `shlex.py` that the environment puts first runs before the check and can end it with status 0. A person edits `pre-push` (a guard file) to start both with `"$python" -I`.

- **Peer-shared models.** A copy offered by a device that is not on the Hub has no publisher and nothing asks about it; member-first copies are checked against the Hub's digest only on a pull that already passed the publisher check.
- **A compromised known namespace.** A first pull of a replaced file from a known publisher passes, because the digest comes from the same Hub listing; an independent digest source (a signed list of release digests, or a transparency record) is needed. Model cards, tags and `base_model` are not read for altered-model markers; only repository and file names are.
- **A server started by a process of its own.** `ServerManager` runs `guarded.verify` in the broker daemon on the default route (`poolhouse-serve up`, the `Client`); with `POOLHOUSE_BROKER_LOCAL=1`, another state file or a backend subclass it runs in the caller's process, under the caller's environment, where `POOLHOUSE_SENTINEL=off` (it needs `POOLHOUSE_SENTINEL_BECAUSE`) turns the load check off.
