# Attack pass 2: session capabilities

A second written break-it pass by a non-author on `docs/design-session-capabilities.md` as on `origin/0.3dev` (507 lines), against
`docs/notes/attack-session-capabilities.md` (H1 to H11 and the four accepted risks). Read from the text; no code was run and the
code was not re-read, so a statement about code is the design's own. Every finding names its fix. Verdict: H1 to H11 are closed
in the text with the residues below; the new mechanisms carry **three holes to fix before S2 starts (N1, N2, N3)** and five medium
ones.

## 2. The four accepted-risk verdicts

| Risk | Verdict | Why |
|---|---|---|
| (a) `file` custody bearer | closed | `act` and named-grant `spend` only, no `spawn`, no `launch` (C5, C7), tests in S5. |
| (b) key readable without S0 | **not closed as worded** | S7 now precedes S8, which fixes the order. But "costs what a double fork costs today" is false after N1 and N2: a double fork spends only its own tree's bounds; a key holder with device-wide counters (8 roots a minute, `MAX_ROOTS`, wrong-response limit) can refuse every other session and evict quiet ones. Say the key holder is a denial lever, not only a root-maker; fix N1 and N2 so it is not. Also the limits sentence names "S7" in sections 2.2, 3 and 5 but "S0" in 3 and 7: one name. |
| (c) log share | closed in text, **hole in the formula** | N3. |
| (d) environment readable | closed | Reject-as-accepted is carried: P2 and P6 before S4, ticket narrows rights and time only. |

## 3. New attacks

| # | Severity | Case | Attack | Hole or ok | Fix |
|---|---|---|---|---|---|
| N1 | **high** | Wrong-response limit, 12 a minute on a device | A keyless process connects to the socket (a sandboxed command can; its ticket calls need the socket) and sends 12 bad `register` frames a minute. If "limited" means further registers are refused, no real session registers on the device. `challenge` is unauthenticated too: unbounded nonces. The 8 new roots a minute is the same lever for a key holder. | **hole** | Count wrong responses per connection with back-off and one notice at the third; a valid response is never refused because of wrong ones. One outstanding nonce per connection, a bound on connections. A reconnect of an existing root (it presents a live token) is exempt from the new-root rate limit and from `MAX_ROOTS`; the rate limit is per anchor, not device-wide, so an unanchored flood cannot spend an anchored person's minute. |
| N2 | **high** | `MAX_ROOTS` 64 and eviction of the quietest idle root | A key holder makes 8 roots a minute for 8 minutes, then keeps them "active" with one cheap call each: every new real session is refused ("every root is active"). Or it makes new roots until the quietest idle root, which is the real session at lunch (no lease), is evicted: its token ends, its commands are refused until the harness restarts, and it loses its older-than-an-hour status. | **hole** | Evict only roots with no live capability (all ended or idle past `idle_retire_s`); a quiet live root is not evicted. Reserve slots for roots with a signed anchor that unanchored roots cannot take. "Active" is defined once (a request that spent or wrote, not any call). An evicted root that presents its token is readmitted as the same root. |
| N3 | **high** | Fair share with the older-roots reserve | (a) The reserve is for old roots as a class: an attacker makes 4 roots, waits an hour, and the 4 old roots take 25 percent each, the whole log including the reserve. (b) The denominator `left / active roots` also applies to old roots: 60 young roots each write one row and every old root's share shrinks to 1/60 of what is left. (c) Eviction re-registers the victim with a new `born`, so the victim loses its old status. | **hole** | Two classes with their own denominators: old roots share the reserve (`reserve left / active old roots`), young roots share the rest. Old status is kept by the digest across eviction. Per-root floor for any root that has written in the last day: the reserve divided by the count of such roots, not a class pool. |
| N4 | medium | Evidence anchor, spoofed by nesting | An agent runs `claude -p ...` (or any harness) from its command. The nested harness's SessionStart hook runs unsandboxed, holds the root key and registers from the person's terminal: it records the person's anchor and is credited a person's statement. The doc covers `tmux new -d`, `script` and `pty.fork`, not a child in the same terminal. | **hole (as before: the old walk had it too)** | At `register` record, as evidence, whether the connecting chain passes through a process bound to another live root (read once, as the anchor is); a root with such an ancestor is cause `agent`. Test `a_harness_started_by_a_session_command_is_not_anchored`. |
| N5 | medium | Windows `[Trust this session]` tap | (a) Every Windows root has no anchor, so every session start asks for a tap: the visit per `claude` start that H1 option 2 warned of. (b) If the card is raised at register, a hostile process makes a card per root (8 a minute): tap fatigue ends with the person trusting an attacker's root, which then gets a person's statement credit, urgent cards and the `program` cause. (c) The card shows the chain "for the card": process names come from argv and are the caller's. | **hole** | Raise the card lazily, only when a request from that root needs the credit (a person statement, an urgent card), one pending per device; bind the tap to the root id and the anchor-less chain facts; show executable paths from the kernel, marked unverified, never argv; require the strong person key's signature, not a tap. Prefer removing the tap: read the console (`GetConsoleWindow` owner and session) as the Windows anchor; mark it a probe. |
| N6 | medium | Anchor read once at `register` | A harness resumed in another terminal (or in `tmux new -d` by an agent) comes back as the same root (same digest, live token presented). If the first anchor is kept it stays credited though the harness left the person's window; if it is re-read, an agent can downgrade a person's session by resuming it in a detached pty. | **hole (undefined)** | Re-read at every `register`; the newest anchor decides and the change raises the quiet notice. A person-session credit is per `{root, anchor}`. |
| N7 | medium | Vouchers, tickets and the store | 8 outstanding vouchers are per capability, and a ticket holds `launch`: 256 tickets x 8 = 2048 vouchers per session, each a reserved name and a record. Tickets are 256 per session x 64 sessions x 64 roots, in memory and snapshotted every 30 s; the 4096 bound counts session tokens only. | **hole** | Count vouchers and tickets per root (for example 64 and 256) and per device, inside one store bound; `a_ticket_flood_cannot_pass_the_store_bound`. |
| N8 | medium | Voucher secrecy and retire-forged | The bound `{pid,start}` makes the voucher useless to anyone else, so the pipe adds nothing, and retiring the child on a wrong presenter inside 120 s is a kill lever for whoever reads the pipe: on Linux a same-user process can open `/proc/<child>/fd/<n>` of the pipe (ptrace-scope does not restrict it) and read or consume the voucher, so the child starts `expired`. A launcher wrapper that forks (`bash -c` without `exec`) redeems from a grandchild and retires its own child `forged`. | **hole, low impact** | A wrong presenter is refused and counted, never retires; the secret and the pipe stay as a second factor. Redeem from a descendant is refused with a plain sentence naming the wrapper. |
| N9 | low | `spawn {child:{pid,start}}` | The parent supplies pid and start; the node does not check that the pid is the caller's child (C1). A parent binds a voucher to any pid, or to a pid that exited and was reused between the read and the call. `spawn` takes a parent-chosen native session id, so a `launch` holder reserves the name of a session that has not started yet. | **ok, two edges** | The node re-reads `start` for the pid at `spawn` and refuses a mismatch. Launcher children get a node-minted session id; only a hook-reported id is accepted for a hook child. |
| N10 | low | Challenge and response | The HMAC covers the nonce and the native id, nothing for harness or purpose, and the root key reaches the library, the CLI, the app and launchers: a key holder registers any digest (N1, H4). Fork and bind: the child blocks on the pipe and does nothing before bind, so a fork-to-bind race has no window; pid reuse needs the start time to match (10 ms ticks on Linux, finer on macOS), so reuse within a voucher's life is not practical. | **ok** | Add the harness and a purpose label to the HMAC input. |
| N11 | medium | S7 and S8 order, windows | (1) Walk gone, replacement absent: S8 needs S6 and S7, so no. (2) 6 says the walk guards re-registration and grants through S7, but S6 adds the quiet takeover that C9 uses instead: which wins in S6 and S7 is not written (if `admit_from` still refuses, takeover cannot work; if S6 overrides it, the walk stops guarding re-registration in S6). (3) From S2 the tokens in `client/` files exist before custody classes (S4, S5): they hold `spawn` and class-grant `spend` with the walk as the brake; say they are `file` custody from S2. (4) The path that makes a subagent by `register` presenting a parent's token (`Node::parent_of`) is not removed in any slice: a token holder mints children with no voucher and no custody. (5) S8 deletes the walk for every user, sandboxed or not, since the user chooses the sandbox: the replacement is unsandboxed `file` and `hook` custody, which is the accepted risk (b). | **hole (2) and (4), notes (3) and (5)** | State in S6 that the takeover replaces `admit_from` and the walk keeps guarding only grants; remove the register-with-token child path in S3 and test `a_child_cannot_register_by_presenting_its_parents_token`; name the default custody in S2. |
| N12 | low | 8 hour ticket end | A used ticket ends 8 hours after issue: a long background command is cut mid-run with a refusal, and a watcher that polls keeps a thief at most 8 hours. The refusal text must say "run it with launch". | **ok** | Add the sentence to the refusal. |

## 4. The cases of AGENTS.md section 1 and the owner's

design. Approval fatigue: **ok except N5**. Takeover by whoever is present: **ok** for a session, with the `idle_retire_s` residue
of H2. Malicious agent: **hole N1, N2, N7**. Compromised without knowing: **ok given S0**, and N4 without it.
