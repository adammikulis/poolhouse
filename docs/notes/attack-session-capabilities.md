# Attack pass: session capabilities

A written break-it pass by a non-author on `docs/design-session-capabilities.md` as on `origin/0.3dev` (`2c19adcda`). Read against
`app/poolhouse-node/src/` (`identity.rs`, `lineage.rs`, `node.rs`, `sessions.rs`, `idle.rs`, `grants/mod.rs`, `grants/calls.rs`,
`api.rs`) and `docs/compromised-agents.md` 3.5 and 4.8. Statements about code were read, not run. Every finding names the fix; the
author applies them to the design before S2 starts.

Verdict: the capability record, the voucher and the re-keying of bounds are sound. The design is **not ready to start S2** until
H1 to H5 are decided in the document. H1 and H2 are design contradictions, not tuning.

## Findings, in order of severity

| # | Severity | Finding | Fix |
|---|---|---|---|
| H1 | high | **The terminal anchor of `compromised-agents.md` 3.5 loses its only basis.** U16, I9 and the `program` cause credit a person's statement or an urgent card only to a request whose lineage contains an *anchored shell* (`in_terminal`, `Anchor::signed`, `lineage::of`). That is the defence against `tmux new -d`, `script`, `pty.fork` and `osascript`. C11 deletes the walk, C1 says no process fact decides anything, and 5 renames the anchor "a trusted root: a root cap id a strong person key signed". Nothing says how a new root becomes trusted. Per session start it is a typed yes (a visit per `claude` start: a regression of onboarding); by the hook credential it is any same-user process (a `tmux new -d` agent hosting `claude` gets a root exactly as the person's terminal does), so the pty escape reopens. 7 answers "none new" and 3.5 is deferred to S6, after S2 to S5 have changed what an anchor is. | Decide the trust path before S2. Option 1 (correct): keep one narrow process read for evidence only, in the node: at `register` the node reads the connecting process's terminal anchor (`{pid,start}` of the session leader with a tty) and records it on the root as a fact for 3.5 and nothing else; no bound, token or grant reads it; U16 and I9 keep their meaning. State that C1 and C11 exempt this reader and name the file. Option 2: per-root trust by a person tap (`[Trust this session]`), once per root, and say the onboarding cost. Do not ship S7 until one is built. |
| H2 | high | **Takeover of a quiet main session needs no proof.** C9 and 2.6: any hook-credential holder that names a main session's native id takes it when `seen_ms` is older than 30 minutes and it holds no lease. A harness paused at a prompt, a long build, lunch, an overnight terminal: all quiet, none holds a lease. The native id is not secret (`~/.claude/projects/*/<id>.jsonl`, `ps`, the hook's own input); the name is a hash of it; `session_lookup` answers with no token. The taker gets the name, so every standing grant of `Grantee::Session{name}` and every `subagents` grant below it (`grants::names`), and the older capabilities end *with every child capability below them*: the real session is refused with "started again" and its workers die. `rebind` needed an enrolled person key and a typed yes; this needs a file read. Today's `admit_from` also needs a shared process. | (a) Takeover by quiet gives the new capability `act` only; `spend` returns when the old token ended itself (SessionEnd, `retire`) or the caller presented the old token. Standing grants do not move on a timer. (b) A takeover raises one quiet-lane notice naming the old session and the time ("a session that stopped 41 minutes ago was started again"); not a prompt. (c) The old children are not ended; they re-parent under the new capability or end only when the old token is presented to `retire`. (d) `session_lookup` takes a token. |
| H3 | high | **Deleting the walk loses protections the design does not replace.** Listed: (1) a token with no recorded lineage spends no grant (fail closed, `lineage_allows`, `Held.lineage`); every new token holds `spend`. (2) A main session registers again only from a process that shares one of its processes (`admit_from`); replaced by a 30 minute timer (H2). (3) Every person-signed act is bound to the terminal it was signed in (`in_terminal` in `enroll`, `unenroll`, the approval bundle; `rebind`); the replacement binds to the *cap id of the session carrying it*, and the carrier of a person's act is a `file` custody session, a bearer file every same-user process can read. A captured signed frame can then be sent by any process that holds that session. (4) `tree_leases` counts across every board and `Waiting` counts per connecting process; both are re-keyed per board root (H4). (5) The only proof that the old harness process is still alive (start time match) goes with the timer. The doc's table 1.4 lists the keys but not these as protections. | (1) `spend` is per custody class: `process` and ticket hold it, `file` holds it only for grants that name the session itself, none for a class grant. (3) A person-signed act is accepted only from the person's session (`person-<machine id>`) or the app, never from an agent session's ticket; the signature also names the custody class. (2), (5) as H2. (4) as H4. Move S7 after S8: until the sandbox lands the walk is the only brake on a double fork for grants and for takeovers. |
| H4 | high | **A root per board multiplies the budget.** `tree_leases` ("on every board") and `Waiting` are device-wide today, keyed by process. 2.2 says the root id "is kept with the name" and 3 re-keys to "root cap id", but names and `Holder` are per board (`Holder{board,name}`), so one native session registered on N boards is N roots, each with 1024 leases, 16 waits, 25 percent of its log, 32 boards. Boards made per root against `MAX_BOARDS` 256 lets four roots take the node. `MAX_ROOTS` then counts the same session N times. | The root is device-wide, keyed by the native digest (`identity::digest(harness, session)`), and every board's capability for that session names the same root id. `MAX_ROOTS` counts digests. Test: `the_same_session_on_two_boards_has_one_lease_bound`. |
| H5 | high | **The voucher can be taken, and a spent one kills a live child.** (a) 2.3 allows "a variable the child clears after reading": the initial environment stays readable by every same-user process for the child's life (`/proc/<pid>/environ`, `KERN_PROCARGS2`); a clear in memory changes nothing. A thief that polls `ps eww` redeems first and holds a `process` token bound to the *thief's* pid; the real child fails. The doc accepts this as "inside the parent's budget", but the thief holds the child's name, grants and the parent's `spend`. (b) Step 4 says a voucher "past its end" is refused and "the first redemption's capabilities end, the child is retired `forged`". Read literally, replaying a spent voucher read from a live child's environment, hours later, retires a healthy child and its subtree: a free targeted kill, no key needed. (c) `spawn` assigns the child's name and writes its identity before redemption; a voucher that expires unredeemed leaves a live-looking session that counts toward `MOST_LIVE_PER_ROOT`; 256 of them stops the parent from spawning, and the injected agent can do it with the `launch` right. No bound on outstanding vouchers. | (a) Ban the variable. The parent forks the child, which blocks reading an inherited pipe; the parent calls `spawn {pid, start}` with the child's id; the node redeems only for that `{pid,start}`; the parent writes the voucher into the pipe. A thief that reads the voucher cannot use it. (b) A second redeem ends the first redemption only inside the voucher's own 120 s; later ones are refused and counted, never retire. (c) Unredeemed children retire `expired` at the voucher's end; `live` counts redeemed sessions only; at most 8 outstanding vouchers per capability. |
| H6 | medium | **`MAX_ROOTS` and the token store can be exhausted, by a hostile process and by honest use.** (a) `idle::sweep(node, board)` runs per board, at `register` and `agents`; `MAX_ROOTS` counts a device. A session that crashed (no SessionEnd) holds its root until someone registers on *that board*; months of crashes across projects reach 128 with no attacker, and every new session on every board is then refused. (b) A hook-credential holder makes 128 roots in a loop (16 per board, a few boards). (c) `MOST_TOKENS` is 2048 and `make_room_for_a_token` only frees sessions idle for 30 days; 256 live sessions per root times 8 roots exceeds it, and caps.json now holds vouchers too. The number 256 x 128 = 32768 is not consistent with 2048 or with `MAX_IDENTITIES`. | A refused registration first runs a device-wide sweep, then evicts the quietest root that holds no lease and has been silent longest (and says so on the notice lane); refusal only when every root is active. One bound for the store: `MOST_TOKENS` is derived from `MAX_ROOTS x MOST_LIVE_PER_ROOT` or the two are lowered to fit, and a root over its fair share of the store evicts its own oldest idle capability first. Rate-limit root creation per minute device-wide. |
| H7 | medium | **Tickets.** (a) 256 live tickets per session, each lasting 15 minutes after last use, one issued per Bash command: a main session at 17 commands a minute, or a loop of short commands, reaches 256 and its own hook then sends commands "with no ticket" and the agent is refused. (b) The `export POOLHOUSE_WORKSPACE_TOKEN=<ticket>` prefix is part of the command text; if the harness runs it as `bash -c` the ticket is in argv and in `ps` for the command's life (and a background command, P5, for hours). (c) The environment is readable by same-user processes (P2 will almost surely fail on macOS and Linux for an unsandboxed process): a ticket protects nothing on a device without S0. (d) An 8 hour end cuts a long background command mid-run. (e) The hook falling back to the session's own ticket when a subagent event carries no `agent_id` makes the subagent act as its parent: spend and attribution move to the parent. | (a) Reuse an unexpired ticket issued for the same session in the last minute, and evict the oldest ticket at the bound instead of refusing. (b) Add probe **P6**: how the harness runs the rewritten command; deliver by `CLAUDE_ENV_FILE` or a descriptor if it is argv. (c) Say in `docs/agent-sandbox.md` that a ticket narrows rights and time, not secrecy, until P2 passes. (e) Fail closed: no `agent_id` where one is expected is no ticket; test `a_subagent_event_without_its_id_gets_no_ticket`. |
| H8 | medium | **The hook credential.** (a) The key itself crosses the socket in every `register` frame: a logged request, a traceback that prints the request, a same-user process that records frames, all read it. (b) It is one secret for roots, for the reporter MAC of 4.8 (`taint_attest`: "read itself clean") and for the library, the CLI, the app and the launchers. 4.8 names "the hook and the node" as the only readers; now four more tools hold it in memory, some inside programs an agent writes and runs. A leak from any one is a root-minting key and a taint-washing key together. (c) S0 denies read and the Read/Edit/Write rules; the sandbox must also deny *write and unlink* of `hook.key` and of `<state>/hooks/`, or a sandboxed command can plant a custody file (misattribute a session's commands) or delete one (refuse them). (d) "A wrong credential is refused and counted": counted is no brake. | (a) Challenge and response: the node hands a nonce, the client answers HMAC(key, nonce, native id); the key never crosses the socket. (b) Derive two keys from `hook.key` (HKDF, purposes `root` and `reporter`); the reporter key is read only by hooks and the node, as 4.8 says. (c) Add the write rules to S8 and to its probes. (d) Rate-limit wrong credentials per minute and raise a card-less notice at the third. |
| H9 | low | **`--agent` as an assertion (C8)** is sound: a command acts as the capability it holds and a mismatch fails. Two edges: `connect()` today also reads native-session variables (`CODEX_THREAD_ID`, `POOLHOUSE_SESSION_*`); under `file` custody they pick a custody file, so the *variable* is a selector again for Codex and for any same-user process. And the hook-reported `session_id` or `agent_id` decides which ticket a command gets. | State that for `file` custody the variable selects, and the file's mode is the only guard (the doc says as much in 2.4; repeat it in C8 so the claim "nothing a command says picks whose secret it uses" is true only for `process` and `hook`). Test: `a_forged_session_variable_cannot_pick_a_hook_custody_file`. |
| H10 | low | **Approval fatigue is "none new" only if the requester counter survives root rotation.** `approvals::fatigue::requester` keys on the main session's name; a hook-credential holder makes a fresh root per burst (up to `MAX_ROOTS`) and each starts with a clean counter and a lookalike name (`claude-<hash>` from a claimed model, `Claimed` not `Verified`). Today any process does this, so it is not a regression, but 7 states "none new" and C3 does not change it. | Count pending cards device-wide as well as per requester; a card from a root less than an hour old shows "a new session". |
| H11 | low | **Program and person sessions are named by the caller.** `<program name>-<machine id>` and `person-<machine id>` replace the terminal: two programs with one name share one root, grants and budget, and a same-user hostile process names itself the person's session. It then takes it over after 30 minutes quiet (H2) or on reading its file. | The person session registers only from the person's CLI or app with the person's key; a program session name carries a hash of its executable path read once at register, as a label. |

## The cases of AGENTS.md section 1 and the ones the owner named

| Case | Attack | Result | Fix or note |
|---|---|---|---|
| Copied or cloned device or pool | Copy `caps.json`, `hook.key`, custody files | **ok** | `process` bindings fail on the clone; a whole cloned state directory is a cloned device as today. |
| Replay | Resend a `register` frame, a `redeem`, a signed act | **hole (H8a, H5b)** | The `register` frame holds the key; a spent voucher kills a live child. Signed acts: nonce `once` holds. |
| Forged or below-threshold signature | Weak key where a trusted root is needed | **hole (H1)** | No signature on capabilities is right; but "a root a strong person key signed" has no defined act. |
| Compromised or malicious member | A pool device names local sessions or a parent | **ok, one test missing** | State that `register`, `spawn`, `redeem`, `ticket` are local-socket methods only and refused from the pool, phone and link transports; test `a_remote_peer_cannot_call_register_spawn_redeem_or_ticket`. |
| Stolen token or key | Copy a custody file or `file` token | **accepted, see (a) below** | `hook` file: S0 only; `process`: nothing. |
| Malicious agent | Mint budget, spawn children, more rights | **hole (H4, H5c, H6)** | Rights subset and root counting hold; the counts have the holes listed. |
| Unknowingly compromised agent | Injected "register a new session", "take the lead's token" | **ok given S0** | Without S0 a `cat` finishes it; same as today. |

## The four accepted risks of section 7

| Risk | Judgement | Condition |
|---|---|---|
| (a) `file` custody is a bearer secret with no lineage check (Codex, the person's CLI, programs) | **Accept, with two changes.** The old check was bypassable and the design says so; but a `file` token also holds `spawn` and `launch` (C5), which a copied file turns into free-standing children, and `spend` for class grants. | `file` tokens hold `act` and `spend` for named grants only; no `spawn`, no `launch`. The person's CLI session signs nothing an agent session may carry (H3). |
| (b) Without S0 a process of the user makes a root by reading `hook.key` | **Accept the cost, reject the order.** It equals a double fork today, so the read is fair; but S1 lands a credential that looks like a control while nothing denies the read, and S7 removes the walk before S8 adds the sandbox. | Move S7 after S8. Write in `docs/limits.md` that the credential is no bound before S0. Do not count it as a bound in any test name or doc until S8. |
| (c) 16 roots on a board can each write 25 percent of a log | **Do not accept as written.** Four roots fill a log and starve the sessions the person is using; with `MAX_ROOTS` 128 and rotation (H10) this is a one-process attack on every board. | Each root's share is `min(25 percent, what is left / active roots)`, and 25 percent of the log is reserved for roots older than an hour. `MAX_LOG_ROWS` stays the last stop. |
| (d) Reading another process's environment is open until P2 | **Reject as an accepted risk; keep it as a probe with a worse-case default.** The answer is known: same-user processes read each other's environment on macOS and Linux unless the sandbox denies it, and a sandboxed command cannot be the only reader that matters. | Say now that a ticket narrows rights and time and gives no secrecy on a device without S0; run P2 and P6 before S4 starts, not inside it. |

## What stays sound

Capabilities recorded by the node, not signed (C2); rights as a subset (C4); the root as the key of every bound; one voucher, one
redemption (with H5 applied); `process` custody bound to `{pid,start}` (the pid cannot be chosen, and a clone has no such
process); refusing every identity-shaped request field; no migration; deleting `rebind`, `terminal.py` and the token directory.
