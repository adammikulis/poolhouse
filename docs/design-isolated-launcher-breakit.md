# Break-it pass: the isolated launcher design

Non-author attack-first review of `docs/design-isolated-launcher.md` at `62e223821` (AGENTS.md section 1, "Attack
first"; the design's own section 14 asked for this pass). Read with it: AGENTS.md, `docs/agent-policy.md`,
`src/poolhouse/coding_workspace.py`, `coding_workspace_state.py`, `activity/source_snapshot.py`, `harnessing.py`,
`claude.py`, `codex.py`, `workspace/coding_turns.py`, `sandbox/{policy,seatbelt,bubblewrap,run,process_tree}.py`,
`guard/autoexec.py`, `serverkeys.py`, `authority.py`, `person.py`, `fleet/wsl.py`, `fleet/projects.py`.

**What this document is not**: an edit to the design. It is evidence for the owner to weigh before the design is
built; several findings are about code that does not exist yet (`isolation.*`, `Workspace.apply`, the AppArmor
profile) and are marked as design-level, not run.

**Environment**: this Mac (macOS 26.6, build 25G70, Apple M4 Max, `/usr/bin/sandbox-exec` present), same device
the design itself used. No Linux or Windows device was reachable (same gap the design records), so every Linux
and Windows claim below is a read of the code or of the design text, not a run; marked **NOT RUN (no device)**.
A claim marked **VERIFIED** was executed in this review, today, with the command or script named; **DESIGN
TRACE** means reasoned from the design text and the code that exists, because the mechanism it depends on is not
yet built; **HELD** means the attack was tried and the design's defence worked as claimed.

## New attacks the design's 45 did not name

Beyond N1–N9 above (ranked by severity), tried and found held:

- **Toolchain-directory grant widened by a hostile project file** (asked for explicitly in the brief): the design's
  own text (8.2) names the exact defence — "a directory is refused… when it holds no executable of the declared
  kind… a `pyvenv.cfg` that names `~/.ssh` gets nothing" — but the *resolution* step ("the real path of the version
  directory the person's own version manager installed") is unbuilt, so this review could not probe a hostile
  `.python-version`/`rust-toolchain.toml` pointing at a symlink farm designed to resolve, after the refusal's
  checks run, to a different real path than the one actually granted (a TOCTOU between "resolve" and "grant", the
  same shape as N7). **Weak, unbuilt, flagged for the implementer**: the grant should be computed from the same
  resolved, `O_NOFOLLOW`-opened path that is later mounted/read-granted, in one step, not resolved once for the
  refusal check and again for the grant.
- **The grant ledger forged by the agent**: not reachable in the design as written, because grants are issued by
  the parent process outside the confinement (I7) and `isolation.grants` does not accept input from inside it; no
  code path was found, today or in the design text, that lets a confined process write to
  `home.state("authority-audit.jsonl")` or an equivalent grant log directly. **Held, by construction** (I3, I7, G1),
  not independently probed since the ledger module does not exist.
- **Resource watchers racing a fork bomb**: see N8 (process count is strengthenable from watched to enforced) and
  A22 (memory is confirmed not enforceable by either `RLIMIT_AS` or the Mach per-task footprint limit on this
  macOS, VERIFIED, `p_mem.py`). The design's own honesty about memory ("`RLIMIT_AS` is not enforced on macOS") is
  correct and should be read, by the implementer, as also ruling out `task_set_phys_footprint_limit` as a
  substitute, since this review found it equally ineffective.
